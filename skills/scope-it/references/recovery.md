# Publication recovery and Map maintenance

Read this for interrupted publication, uncertain creations, retrieval or amendment of an existing Map, legacy Map markers, or a delivery audit. Keep recovery records outside the formal Map; they do not supply missing source content, invocation consent or write authority.

## Resume an interrupted phase

Recover exact drafts, approvals and successful writes. Read back actual content and identities before deciding what remains. Reuse complete approved work; repair only missing approved operations, asking about ambiguity or changed writes. Continue the unfinished phase instead of rerunning completed sources.

Look up uncertain creations before retrying. After a Map creation timeout without an ID, bind only a unique marker-and-approved-content match to its read-back comment ID/URL. Multiple indistinguishable matches remain unresolved.

Preserve successful writes, siblings and unrelated content. Verify each remaining write and both relationship axes before dependent work. A vague summary or missing draft requires the exact source content and applicable approval, not invented tickets or progress fields.

## Retrieve or amend the Map

For a later retrieval, return the parent and published canonical Map without restarting planning. Its embedded **Start the Next Ticket** protocol lets another session continue without this skill or the planning chat.

Approved amendments edit the canonical comment's marker-bound block in place; preserve surrounding content and existing Scope/Ticket bytes. Later ordinary parent comments do not change the Map identity. When the block uses legacy `scope-it-remake` markers, edit that same block and comment instead of creating a second Map or changing its markers.

Return source-content changes to their responsible source for its required checks and publication approval before affected downstream work. Preserve unchanged artifacts and approvals. Changes to ownership, delivery paths or shared responsibilities need an approved Map amendment.

## Audit or repair drift

A requested delivery audit reads the published agreement and repository workflow; corrective writes require approval. Report mismatched content, metadata, attachments, relationships or canonical Map identity, and withhold affected completion until resolved. Preserve completed work while obtaining only the missing repair decisions. Failed readback of a supported capability remains unresolved rather than becoming an unsupported fallback.
